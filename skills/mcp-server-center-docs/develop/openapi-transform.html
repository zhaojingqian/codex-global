OpenAPI 转为 MCP

作者: 飞超 · 更新时间: 2026-01-25
  • 无需编写代码，支持将 OpenAPI 一键转换为 MCP Tools
  • 支持打通 BUC 免登，详见 BUC 应用免登

操作步骤

新建 MCP Server

前往 Aone 开放平台，右上角"注册 MCP Server"。注意，当前 MCP Server 要求绑定在平台下，如果没有合适的平台，需要先新建平台。

如果已有平台，也可以从平台下的 MCP 管理进入。

填写 MCP Server 注册表单，接入类型选择 Open API Transform，该接入类型需要填写 OpenAPI 的预发和线上 endpoint。

MCP Server 注册完成后，会跳转到 MCP Tool 管理页面。

API -> MCP Tools

转换过程共 5 步：

1. 上传/输入 OAS / Swagger 3.0.x 文档（Open API 描述文件）。如果你当前没有现成的 OAS 文档，可以借助 ChatGPT / DeepSeek / Qwen 等生成。

2. 选择需要转换为 MCP Tool 的 API。当前步骤会解析上述 OAS 文档，通过表格的方式展示 API 基本信息，请确保 OAS 文档正确，否则可能无法正常解析。

3. API 转换为 MCP Tool

在当前步骤下，平台会基于默认的转换规则（见下），基于 API 的描述信息，将其转换为 MCP Tool。可以在当前页面看到 MCP Tool 的名称、描述、入参等信息，也可以看到 MCP 入参实际对应 API 参数及参数位置。

点击"编辑"按钮，可手动调整 MCP Tool 相关信息。

转换规则介绍

转换后的 MCP Tool 的配置通过一个 JSON 来表示，包含以下几部分：
  1. name：Tool 的名称，默认与 API 的 operationId 一致
  2. description：Tool 描述，默认与 API 的 description 一致
  3. inputSchema：Tool 入参描述，类型是一个 object
  4. apiPath：API 的路径
  5. apiMethod：API 请求方法
  6. contentType：API 请求存在 requestBody 时需要，比如：application/json、application/x-www-form-urlencoded
  7. inputMappingRule：入参转换规则，用于描述 Tool 的参数（inputSchema）如何与 API 的参数对应。inputMappingRule 是一个对象，对象的 key 为 API 参数位置和名称，value 为工具入参/上下文参数/常量。
    • 注意：如果 value 是工具的入参或上下文参数时，需要加上 $ 前缀，常量不需要 $ 前缀
  8. outputMappingRule：API 返回结果转换规则，可以编写一段自定义的规则代码（QLExpress），处理 API 返回的结果（暂未实现）

进阶用法：
支持通过 ctx 获取上下文相关信息：在实际调用 API 时，我们可能需要将用户工号等信息作为 API 的参数，但又不希望显式地作为 MCP Tool 的参数，希望能直接从当前上下文获取。这种情况下，我们可以在 inputMappingRule 中通过 $ctx.xxx 的方式引用上下文变量。

比如在调用某平台相关接口时，我们需要传递 operator 参数来表示当前操作人员，就可以从上下文获取： 
"inputMappingRule": {
  "body.operator": "$ctx.user.empId"
}

4. 预发测试

转换完成之后，进入下一步，我们会获得一个预发环境的 MCP Server 的 SSE 链接，可以前往 MCP Inspector 或复制链接前往 Aone Copilot、Cline、Cursor 等客户端验证。

确认预发验证通过之后，点击下一步即可将 MCP Tool 发布线上。

5. 发布线上

点击前往主页，可进入 MCP 服务详情页。

MCP Tool 管理

管理界面已迁移到 "发布" tab 里

完整走完上述流程之后，我们就得到了一个可以正常使用的 MCP Server。后续如果想对 MCP Tool 进行修改，或需要增加更多的 Tool，可以在 MCP 服务详情页操作。

注意：上述操作仅当前 MCP Server 负责人可见。
