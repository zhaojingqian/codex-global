单应用多 MCP Server

作者: 飞超 · 更新时间: 2026-05-28
本功能要求 mcp-lite-hsf-server-starter 1.3.0 或更高版本

背景

默认情况下，mcp-lite-hsf-server-starter 会将应用中所有 @Tool 方法注册到同一个 HSF Provider（即同一个 MCP Server）。当一个应用包含多个业务域的工具时，所有工具堆在一起不便于按业务维度独立管理。

从 1.3.0 版本开始，你可以在一个 Spring 应用中声明多个 MCP Server，每个 Server 暴露指定的工具子集，注册为独立的 HSF Provider。

快速上手

Step 1：用 @Tool.Group 给工具分组

在 @Component 类或 @Tool 方法上添加 @Tool.Group 注解：

@Component
@Tool.Group("code")
public class CodeTools {
    @Tool(name = "search_code", description = "搜索代码")
    public String searchCode(@ToolParam String keyword) { ... }

    @Tool(name = "get_file", description = "获取文件内容")
    public String getFile(@ToolParam String path) { ... }
}

@Component
@Tool.Group("ci")
public class CiTools {
    @Tool(name = "trigger_pipeline", description = "触发流水线")
    public String triggerPipeline(@ToolParam long id) { ... }
}

@Component
public class GeneralTools {
    // 没有 @Tool.Group → group = "default"
    @Tool(name = "ping", description = "健康检查")
    public String ping() { return "pong"; }
}
  • 类级 @Tool.Group 对该类下所有 @Tool 方法生效
  • 方法级 @Tool.Group 优先级高于类级
  • 未标注 @Tool.Group 的工具，group 为 "default"

Step 2：声明 HsfMcpServerRegistration Bean

在 Spring @Configuration 中注册多个 HsfMcpServerRegistration Bean，每个 Bean 对应一个独立的 MCP Server：

@Configuration
public class McpServersConfig {

    @Bean
    public HsfMcpServerRegistration codeServer() {
        HsfMcpServerRegistration reg = new HsfMcpServerRegistration("my-app-code");
        reg.setGroups(Arrays.asList("code"));
        return reg;
    }

    @Bean
    public HsfMcpServerRegistration ciServer() {
        HsfMcpServerRegistration reg = new HsfMcpServerRegistration("my-app-ci");
        reg.setGroups(Arrays.asList("ci", "default"));
        return reg;
    }
}

启动后将注册两个独立的 HSF Provider：

HSF serviceVersion包含的工具来源
my-app-code search_code, get_file group="code"
my-app-ci trigger_pipeline, ping group="ci" + group="default"

工具选择方式

HsfMcpServerRegistration 提供三种方式指定工具：

方式字段说明
按分组批量引入 groups 引入一个 @Tool.Group 下的所有工具
按名称精确引入 tools 引入指定 @Tool(name = "...") 的单个工具，不受 group 限制
包含所有工具 includeAllTools 设为 true 时，该 Server 包含应用中所有 @Tool 方法。与 groups / tools 互斥，不能同时设置，否则启动报错

当 includeAllTools=false（默认值）时，最终该 Server 的工具集 = groups 匹配的工具 ∪ tools 匹配的工具。

@Bean
public HsfMcpServerRegistration ciServer() {
    HsfMcpServerRegistration reg = new HsfMcpServerRegistration("my-app-ci");
    // 批量引入 "ci" 和 "default" 分组的全部工具
    reg.setGroups(Arrays.asList("ci", "default"));
    // 精确引入其他分组中的单个工具
    reg.setTools(Arrays.asList("search_code"));
    return reg;
}

网关侧注册

在 Aone 开放平台中，每个 HsfMcpServerRegistration 需要单独注册为一个 MCP Server Specification：

MCP Server 名称类型HSF 映射
my-app-code hsf my-app-code
my-app-ci hsf my-app-ci

网关侧无需任何代码改动。每个 Registration 在网关看来就是一个独立的 MCP Server。

向后兼容

如果你的 Spring 容器中没有声明任何 HsfMcpServerRegistration Bean，行为与之前完全一致：所有 @Tool 方法注册到同一个 MCP Server，使用全局 McpHsfProperties 配置。

从单 Server 迁移到多 Server

已上线应用从单 Server 模式切换到多 Server 模式时，必须留意 HSF serviceVersion 的变化，否则网关会路由到不存在的服务，导致线上调用全部失败。

HSF serviceVersion 的变化

两种模式下 HSF Provider 的 serviceVersion 来源完全不同：

模式serviceVersion 来源
单 Server（无 Registration Bean） mcp.hsf.server.name ↩ project.name，可被 useAppGroupAsName=true 进一步覆盖为 SIGMA_APP_GROUP
多 Server（≥1 个 Registration Bean） 直接使用 reg.getName()，不再读取 mcp.hsf.server.name / project.name / useAppGroupAsName / SIGMA_APP_GROUP

一旦容器中出现任意一个 HsfMcpServerRegistration Bean，原来基于单 Server 模式注册的那个 HSF Provider 会立即消失，网关用旧名字路由将得到 NoProviderException。

滚动发布期间的中间态

升级新版本时，老机器（serviceVersion = my-app）和新机器（serviceVersion = my-app-code / my-app-ci）在 ConfigServer 上是两组完全不同的服务，没有任何重叠：

  • 调用旧名字 my-app 时，只能命中尚未升级的老机器
  • 调用新名字 my-app-code 时，只能命中已升级的新机器
  • 发布期间机器数较少时，provider 列表会出现明显抖动

推荐迁移方式：保留原 serverName + includeAllTools

让其中一个 HsfMcpServerRegistration 的 name 等于原 mcp.hsf.server.name / project.name（如果开了 useAppGroupAsName，则等于实际生效的 SIGMA_APP_GROUP 值），并设置 includeAllTools=true，这样老的网关路由继续访问到所有工具，新拆出去的 Server 在网关侧另行注册即可：

@Configuration
public class McpServersConfig {

    // 保留原 serverName，包含所有工具，老路由完全不受影响
    @Bean
    public HsfMcpServerRegistration mainServer() {
        HsfMcpServerRegistration reg = new HsfMcpServerRegistration("my-app");
        reg.setIncludeAllTools(true);
        return reg;
    }

    // 新拆出去的 Server，包含特定 group 的工具，在网关侧另行注册
    @Bean
    public HsfMcpServerRegistration extraServer() {
        HsfMcpServerRegistration reg = new HsfMcpServerRegistration("my-app-extra");
        reg.setGroups(Arrays.asList("extra"));
        return reg;
    }
}

使用 includeAllTools=true 的好处：

  • 不需要把所有 @Tool.Group 一一列出来，新增工具时不用更新 Registration
  • 语义清晰：「保留原 Server 的全量工具行为」
  • 与 extraServer 的工具集自然存在重叠（extra 组工具同时在两个 Server 暴露），这是迁移期间的预期行为

原来使用 useAppGroupAsName 的应用

如果你的应用原来是靠 mcp.hsf.server.use-app-group-as-name=true + SIGMA_APP_GROUP 模式工作的（参考 HSF 多套环境适配），切换到多 Server 模式后这条路径完全失效——starter 不会再读取 SIGMA_APP_GROUP。

这意味着如果你按相同 Registration Bean 配置在多个 Aone 应用分组中部署同一份代码，所有分组都会以同一个 reg.getName() 注册 HSF Provider，原本通过 SIGMA_APP_GROUP 区分日常/预发/正式或不同分组的能力就丢了。

临时解决方案：在 @Bean 方法里手动读取环境变量来构造 name：

@Bean
public HsfMcpServerRegistration mainServer() {
    String appGroup = System.getenv("SIGMA_APP_GROUP");
    String name = appGroup != null ? appGroup : "my-app";
    HsfMcpServerRegistration reg = new HsfMcpServerRegistration(name);
    reg.setIncludeAllTools(true);
    return reg;
}

行为规则

场景行为
容器中 0 个 Registration Bean 向后兼容：全部 @Tool 注册为一个 MCP Server
容器中 N 个 Registration Bean 注册 N 个独立 MCP Server，各按 groups + tools（或 includeAllTools）分配工具
工具未被任何 Registration 引用 该工具不注册，输出 WARN 日志（容器中存在 includeAllTools=true 的 Registration 时，该检查跳过）
两个 Registration 引用了同一个 group 正常注册，所有相关 Server 都包含该 group 的工具，启动时输出 INFO 日志：group 'X' is included by multiple servers: [...]
不同 Registration 的 tools 引用了同一个工具 正常注册，所有相关 Server 都包含该工具
includeAllTools=true 同时设置 groups 或 tools 启动报错（IllegalArgumentException）：语义冲突
tools 引用的工具名称不存在 忽略，输出 WARN 日志
timeout / authorizedClients 等配置 统一使用全局 McpHsfProperties
全局 name / useAppGroupAsName 在多 Server 模式下失效，以 reg.getName() 作为 HSF serviceVersion

方法级 Group 覆盖

如果一个类中有个别方法需要归属到不同的 group，可以在方法上添加 @Tool.Group，优先级高于类级：

@Component
@Tool.Group("code")
public class MixedTools {

    @Tool(name = "search", description = "搜索代码")
    public String search() { ... }  // group = "code"（类级）

    @Tool.Group("ci")
    @Tool(name = "build", description = "触发构建")
    public String build() { ... }   // group = "ci"（方法级覆盖）
}

常见问题

Q: 多 Server 模式下 ToolInterceptor 如何生效？

所有 Server 共享全局的 ToolInterceptor 列表，不支持按 Server 隔离。

Q: @Tool.Group 和之前版本冲突吗？

不冲突。@Tool.Group 注解在之前版本中已存在，仅用于 Aone 开放平台页面的分组展示。1.3.0 起，该注解同时用于多 Server 模式下的工具分组。

Q: 同一个工具可以被多个 Registration 引用吗？

可以，并且不区分引入方式：

  • 同一个 group 出现在多个 Registration 的 groups 中
  • 同一个工具名出现在多个 Registration 的 tools 中
  • 某 Registration 设置 includeAllTools=true，其他 Registration 通过 groups / tools 引入子集

以上场景都不会冲突，工具会被注册到所有引用它的 Server。需要注意网关侧的调用路由——同一工具可以暴露在不同 Server 上以做权限隔离或差异化配置。
