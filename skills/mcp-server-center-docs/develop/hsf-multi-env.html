HSF 多套环境适配方案

作者: 飞超 · 更新时间: 2026-04-27
注意：本方案要求 mcp-lite-hsf-server-starter 1.0.8 或更高版本

背景

app-center 应用部署在多套环境（以 production 环境级别为例，app-center 有灰度环境、正式环境、多套正式环境）。发布 HSF 服务时，多个应用分组会将 HSF 服务发布到同一个 HSF 环境分组。从 MCP 网关发起调用时，HSF 框架会随机选择一台机器，导致调用结果是随机的。

HSF 路由规则可以支持在调用阶段根据自定义策略决定路由至 Provider 指定机器分组，但需要在 HSF 控制台维护额外的 groovy 脚本。咨询了 HSF 侧的项升同学，他不建议使用路由规则，而是建议根据环境或应用分组发布不同的 HSF 服务。

解决方案

  • mcp-lite-hsf-server-starter 新增配置项 mcp.hsf.server.use-app-group-as-name=true（默认为 false）
    • starter 识别该配置，根据 SIGMA_APP_GROUP 环境变量（对应 Aone 应用分组名称）来发布 HSF 服务
    • 也就是说，该配置为 true 时，不同应用分组将发布不同的 HSF 服务
  • MCP Server 新增配置项 hsf.app-group，让开发者指定对应的应用分组

配置流程

  • 升级 mcp-lite-hsf-server-starter 到 1.0.8 或更高版本
  • 在应用的 application.properties 新增配置 mcp.hsf.server.use-app-group-as-name=true
  • 前往开放平台，打开 MCP Server 的设置页面，在选项中填写 Aone 应用分组名称，注意预发和线上环境需要分别填写

场景举例

case1：Aone 应用中心

app-center（Aone 应用中心）在 HSF 中心环境分组下，有多个应用环境和应用分组（灰度、热备、正式），但其中只有正式环境下的分组可以提供有效且稳定的 MCP 工具。为了确保工具调用结果的稳定性，Aone 应用中心采用了以下配置：

# Spring 应用配置
mcp.hsf.server.use-app-group-as-name=true

# MCP Server 选项（预发环境）
hsf.app-group=app-center_prehost

# MCP Server 选项（正式环境）
hsf.app-group=app-centerhost

case2：工单平台

工单平台通过一个 Aone 应用 + 多个应用分组来承载内部工单和外部工单。

工单平台提供了两个 MCP Server，分别用于内部工单场景和外部工单场景，并通过以下配置 "绑定" MCP Server 与应用分组。

# Spring 应用配置
mcp.hsf.server.use-app-group-as-name=true

# 内部 "workorder工单平台MCP" 的配置
hsf.app-group=ticketshost

# 外部 "tickets工单平台" 的配置
hsf.app-group=tickets_outer_prod_host

进阶方案

在前面的方案中，一个 MCP Server 只能关联一个应用分组，且开发者需要提前在开放平台中指定分组。而在一些更为复杂场景（例如 AIDC WorkAI 多租户场景）中，开发者期望在创建 MCP 会话时，或是在调用 MCP 工具时，动态指定 HSF 调用的目标应用分组。

为此，我们提供了更加灵活的 "路由规则" 能力，允许开发者动态指定应用分组，同时支持了 HSF 跨单元调用。

配置流程

Step-1 应用配置

  • 升级 mcp-lite-hsf-server-starter 到 1.0.8 或更高版本
  • 在 application.properties 新增配置 mcp.hsf.server.use-app-group-as-name=true

Step-2 开放平台配置

开发者前往 Aone 开放平台，为 MCP Server 声明多个路由规则，语法如下：

  • hsf.route.rules.<rule>.configserver-center=注册中心 — configserver-center 可选，不填表示不进行跨单元调用
  • hsf.route.rules.<rule>.app-group=应用分组 — app-group 必填，填写对应的 Aone 应用分组名称

AIDC WorkAI 多租户场景示例：

# 定义三个路由规则名称： lazada_sg_route, daraz_sg_route, arise_de_route
hsf.route.rules.lazada_sg_route.configserver-center=rg-sg-pre
hsf.route.rules.lazada_sg_route.app-group=logistics-lbs-management_rg_sg_lazada-os30-pre_prehost
hsf.route.rules.daraz_sg_route.configserver-center=rg-sg-pre
hsf.route.rules.daraz_sg_route.app-group=logistics-lbs-management_rg_sg_daraz-os30-pre_prehost
hsf.route.rules.arise_de_route.configserver-center=rg-de-2-pre
hsf.route.rules.arise_de_route.app-group=logistics-lbs-management_rg_de_2_arise-de46-pre_prehost

# 默认的路由规则，当规则数量大于 1 时，必须指定该配置项
hsf.route.default-rule=lazada_sg_route
注意：修改 configserver-center 后，可能无法立即生效。如果配置不生效，请联系当前文档的负责同学重启网关服务。

创建会话

【该能力暂未支持】你可以通过 MCP 连接地址的 URL 参数指定路由规则：

https://mcp.alibaba-inc.com/some-server/sse?hsfRouteRule=arise_de_route

工具调用

在调用工具时，客户端可以通过 _meta.hsfRouteRule 指定本次调用使用的 rule：

如果无法传递自定义的 _meta 字段，你也可以通过 arguments 中的 "_meta.hsfRouteRule" 进行指定：

{
  "method": "tools/call",
  "params": {
    "name": "tool_name",
    "arguments": {
      // 正常的工具参数
      "arg1": "value1",
      "arg2": 12345,

      // 指定所要使用的路由规则
      "_meta.hsfRouteRule": "lazada_sg_route",

      // 添加任意业务数据（将通过 HSF RPCContext 传递给下游）
      "_meta.hsfAttachments": { "_GL_K": "LAZADA_SG" }
    }
  }
}

如果没有提供 hsfRouteRule，或者提供的 hsfRouteRule 不是一个有效的规则，则 MCP 网关将使用 hsf.route.default-rule 作为本次调用的路由规则。
