代理已有 MCP Server

更新: 飞超 · 更新时间: 2026-01-25

简介

Aone MCP 网关支持代理已有的 MCP Server。通过该能力，开发者可以将已有的 MCP Server（使用自定义域名）注册到 Aone 开放平台，并将其 "转换" 为 Aone 上的 MCP Server，使得那些已对接 Aone MCP 的 Agent（例如 Aone Agent）能够方便地使用 MCP 工具。

通过 Aone MCP 代理后，外部鉴权由 Aone MCP 网关负责，我们支持标准的 OAuth2 授权与「基于代码平台 Private Token 的简易鉴权」，具体见该文档。内部鉴权由 MCP 开发者进行配置，一般采用自定义请求头方式，详见本文下方。

接入流程

打开 MCP Server 注册页面，在表单中填入 MCP Server 的基本信息，接入类型选择 SSE 或 Streamable HTTP，并填写预发地址和正式地址：

表单填写说明：

  • 接入类型要根据已有 MCP Server 来决定
    • 两种都支持时，建议优先选择 Streamable HTTP
  • 预发和正式地址都不能为空
    • 如果没有预发地址的话，可以和正式地址填写一样的值
  • Aone MCP 网关内部有控制域名访问的白名单，新增域名需加白后才能使用，否则连接会报错。
    • 域名加白请联系本文负责人，联系时请提供 "MCP Server 的详情页链接"
    • 详情页链接示例：https://open.aone.alibaba-inc.com/mcp/server/code

内部鉴权说明

开发者可通过 HTTP 请求头配置 来实现内部鉴权。例如开发者可生成一个 API Key，并将其配置到自定义请求头中：

mcp.headers.X-Api-Key=api-key-for-aone-mcp

Aone MCP 网关向已有 MCP Server 发起工具调用时，会带上 API Key，以证明请求来自 Aone MCP 网关。网关不限制具体的请求头名称或 key 格式，开发者可自行决定。

此外，开发者也可通过 $ctx.user.empId 在指定请求头中获取当前的 BUC 用户工号：

mcp.headers.Buc-Emp-Id=$ctx.user.empId

扩展选项

代理已有 MCP Server 时，Aone MCP 网关支持以下扩展选项（其他配置详见 调整 MCP Server 的选项）

选项默认值说明
proxy.base-url自定义 SSE 代理（或 Streamable HTTP 代理）客户端的 baseUrl
proxy.initialization-timeout120s代理客户端的初始化超时时间，默认为 120s
proxy.request-timeout20s代理客户端的请求超时时间，默认为 20s（当你的工具调用耗时较长时，可以适当调整该配置）

注意事项

  • 固定请求头会在每个请求中提供，包括获取初始化、获取工具列表、调用工具；而动态请求头仅在调用工具时才提供。
    • 固定请求头含义详见 HTTP 请求头配置 文档
  • 当用户通过 OAuth2 完成外部鉴权时，headers 中默认会提供 BUC OAuth2 Token
    • 被代理的 MCP Server 可以选择校验该 token，或是开启 BUC 应用免登
    • "BUC OAuth Token" 或 "免登 Ticket" 与动态请求头一样，Aone MCP 网关仅在调用工具时才会提供
  • 敏感配置请使用 "请求头加密功能"，详见 HTTP 请求头配置
