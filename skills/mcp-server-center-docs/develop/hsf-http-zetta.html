HSF / HTTP 接口转 MCP【ZETTA】

作者: 月侠 · 更新: 唯星 · 更新时间: 2026-04-21

本文介绍如何通过 Aone 开放平台，将已有的 HSF / HTTP 接口转化为 MCP Server

通过该方式进行接入的 MCP Server 底层使用 zetta 网关，与其他接入类型（底层 Aone 开放平台的 MCP 网关）有一些差异。zetta 网关上的 MCP Server 用法可移步：Welcome to ZettaGate

注册 MCP Server

前往 Aone 开放平台，选择右上角的【注册 MCP Server】

接入类型选择【Interface Transform】

选择【单元】如没有特殊需求，选择"中心"即可，默认支持以下两种鉴权方式：

系统间授权BUC OAuth（集团内使用）
携带可观测和可信身份 Header 在系统间调用（用户可自由选择使用封装好的 SDK 或自行添加相应 Header） 内部用户通过 BUC OAuth 身份使用，内部用户使用时，自动弹出 BUC 授权界面

添加工具

注册 MCP Server 后，点击【发布】tab，点击添加工具，支持新建工具或添加其它【Interface Transform】类型的 MCP Server 下的工具

选择 HSF / HTTP 后，填写相应的接口信息、安全信息和参数描述，点击下一步完成新建

点击发布预发/发布线上，即可发布到相应的环境

使用 MCP

添加访问控制

3.23 开始新创建的 MCP，无需添加访问控制，用户可以直接通过 OAuth 访问

点击访问控制，点击添加使用方，【系统间授权】添加对应的 Aone 应用，【BUC OAuth】添加对应的用户。

添加完成后，即可通过对应的授权方式开始使用。

1、获取 MCP 服务地址：

2、使用 MCP 服务

  • 系统间授权使用：可参考 MCP Client 接入
  • 用户授权使用：复制服务地址到对应的 Agent 应用中使用（如 Cursor、Qoder 等），也可以点击【添加到客户端】一键添加。

在开放平台上调试

【系统间授权】的 MCP 支持在平台上调试/立即使用，其它类型的 MCP 可以前往 Aone MCP Inspector 进行调试。

HSF/HTTP 中如何获取到调用的用户信息

详见：参数透传支持来源和去向位置以及参数

注意：HSF RpcContext 中只会取 Header Value 中的第一个值！

Zetta 默认会将上游用户传递的 x-zetta- 开头的 Header (大小写不敏感) 向下游工具 HSF RpcContext / HTTP Header 进行透传 (读取时按大小写不敏感读取)，透传后会移除 x-zetta- 前缀。

另外 Zetta 生成（与上游用户传递有所区别，以下不需要去掉 x-zetta- 前缀）并透传以下 Header：

字段名目标Header 名含义
uidhsf rpc context / http headerx-zetta-gateway-uid经过 OAuth 等认证的用户 ID
unamehsf rpc context / http headerx-zetta-gateway-uname经过 OAuth 等认证的用户 Name，仅在部分认证方式下存在
unicknamehsf rpc context / http headerx-zetta-gateway-unickname经过 OAuth 等认证的用户 NickName，仅在部分认证方式下存在
agentIdhsf rpc context / http headerx-zetta-gateway-agent-id目前代表在 NCS Auth 场景下的 agentId
