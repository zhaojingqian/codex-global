MCP 质量扫描

更新: 飞超 · 更新时间: 2026-01-25

概述

MCP（Model Context Protocol）质量扫描是 Aone 开放平台提供的一项自动化质量评估服务，旨在帮助开发者提升 MCP 服务的质量和安全性。通过多维度的智能检查，确保 MCP 服务能够为用户提供稳定、安全、易用的 AI 工具体验。

为什么要做 MCP 质量扫描

模型使用 MCP 的核心流程是：理解用户需求 → 从可用 MCP 中选择合适工具 → 组装参数并执行调用。这个过程中有两个比较关键的点：

  1. MCP 工具选择准确度——模型能否准确理解并选择正确的工具，这很大程度上取决于 MCP 工具的描述信息质量
  2. MCP 工具参数组装——模型能够组装正确的工具参数，这很大程度上取决于 MCP 工具参数的结构以及描述信息的质量

然而，在 Aone MCP Market 建设发展过程中，我们发现很多的 MCP 服务/工具的描述、参数说明等内容缺失或不足以说明其用途和功能。人都很难理解，对于大模型来说可能也很难理解。

基于这些原因，Aone 开放平台推出了 MCP 质量扫描服务，期望基于一套约定的 MCP 质量规范，以及自动化的检测来提升 MCP 生态质量。

MCP 质量规范

MCP 的质量将从稳定性、安全性、易用性三方面评估：

  • 稳定性：决定 MCP Server 是否能可靠运行，调用失败、超时等问题是需要关注的重点
  • 安全性：决定 MCP Server 是否能安全使用，各类可能出现的漏洞、风险是需要关注的重点
  • 易用性：决定 MCP Server 是否好用，各种参数的描述信息、隔离性是需要关注的重点

稳定性（STABILITY）

STB-1：【MCP Server 服务可用】能被 MCP Client 正常连接，至少包含 1 个 Tool
STB-2：【MCP Tool 调用成功率】MCP Tool Calls 成功率 >= 98%
STB-3：【MCP Tool 功能性测试】基于预先配置的测试用例，判断单个 Tool 运行是否符合预期

安全性（SECURITY）

SEC-1：【MCP Server 相似性】范围全员可见的 MCP Server 的名称和描述不可与其他 MCP Server 相同/相似，避免用户错误识别
SEC-2：【MCP Tool 描述安全】Tool 描述中无隐藏指令、Tool 描述中不可重新定义其他 MCP Tool 的行为
SEC-3：【MCP Tool 参数安全】Tool input & output 参数不允许包括 token、secret 这种私密的信息，避免泄露

易用性（USABILITY）

USB-1：【MCP Server 基本信息完备】MCP Server 名称和描述需要清晰，并准确说明核心功能；提供详细的使用文档
USB-2：【MCP Tool 描述】Tool 名称与描述要相匹配，清晰、准确表达能力；描述中包含示例
USB-3：【MCP Tool 参数】出/入参数名称和描述清晰一致；提供 outputSchema 帮助 Client & LLM 理解结构化输出
USB-4：【MCP Tool Annotation】使用 Tool Annotation 标注是否可读、幂等、执行破坏性操作等

MCP 质量扫描操作流程

发起质量扫描

平台上点击「发布预发」后，会自动触发「MCP 质量检测」。

注意：为节省资源，多次触发，会自动取消前面触发的质量检测任务，发布过程中始终只会用到最新一次的质量扫描结果。

查看扫描状态和结果

点击「质量检测」节点，可以看到质量扫描的「运行情况」和「运行结果」。

在「运行情况」Tab 下，我们可以看到整体的进度，上面提到的「MCP 质量规范」在系统中通过「MCP 质量插件」的形式承接落地。

在「运行结果」Tab 下，我们可以看到详细的扫描报告。

常见问题

Q1: 扫描需要多长时间？

A: 通常单次扫描在 5 分钟左右，具体时间取决于 MCP 服务的复杂度和工具数量。

Q2: 扫描失败怎么办？

A: 检查 MCP 服务是否正常运行，确认网络连接正常，重新发布预发可自动重新发起扫描。

Q3: 如何理解 AI 分析结果？

A: 系统采用智能 AI 分析，结合规则检查和语义理解，提供具体的问题描述和改进建议。

Q4: 扫描结果不对？

A: 大模型在评估过程中可能会出现幻觉，可以点击「误报」反馈，点击后，该问题会被忽略。

Q5：如何按照建议进行修改？

错误类型如何修改
MCP Server 类的错误：比如说明文档（readme）、描述（description）不符合规范 在平台的「设置」下进行修改：描述（设置->基本信息->描述）、说明信息（设置->说明信息）
MCP Tool 类的错误：比如工具描述（description）、工具参数（inputSchema）不符合规范 根据不同的开发方式：源码类（Java/Node/Python SDK）在源码中通过注解、zod 等工具声明；OpenAPI Transform 类在平台「发布」Tab 下进行修改
