MCP Server 接入指南

作者: 飞超 · 更新时间: 2026-01-25

基础信息

MCP Provider（即 MCP 工具的提供方）通过接入 Aone MCP 网关，对外提供 MCP Server 能力。接入后，Provider 可以将 MCP Server 上架到 MCP 市场，方便其他用户使用、或被其他系统集成。

Aone 开放平台 MCP 市场：https://open.aone.alibaba-inc.com/market

接入要求

  • 对接 MCP 网关时，Provider 需要选择一个已有的 OAuth 授权服务器
  • Provider 需正确消费授权服务器颁发的访问令牌（access_token），进行必要的身份认证和权限验证

选择已有的授权服务器

对于常用的身份类型，Aone 开放平台已提前对接好，MCP Provider 可以在注册时直接选择。

（常规开发者默认只能选择 BUC OAuth2，如需切换请联系系统管理员）

BUC 授权服务器

当你的系统使用 BUC 作为用户体系，并围绕 BUC 用户进行功能设计和权限验证时，你可以选择 BUC 作为授权服务器。

授权阶段

客户端初始化授权流程后，Aone MCP 网关会将授权委托给 BUC OAuth，用户在 BUC 系统中进行身份认证后，跳转回客户端回调页面并完成授权，客户端获取 Aone MCP 网关颁发的 access_token（该 token 以 mcpa_ 开头）。

授权阶段由客户端、网关和 BUC 系统共同完成，MCP Provider 一般不用关心。如果感兴趣的话，可以查看该文档。

调用阶段

授权完成后，客户端可以获取网关颁发的 access_token（以 mcpa_ 开头）。客户端在连接 MCP SSE 地址或发起工具调用请求时，会在 Authorization 请求头中带上该 token：

┌──────────────┐      ┌──────────────────┐      ┌─────────────┐      ┌─────┐
│  MCP 客户端   │      │  Aone MCP 网关    │      │ MCP Provider │      │ BUC │
└──────┬───────┘      └────────┬─────────┘      └──────┬──────┘      └──┬──┘
       │                       │                        │                 │
       │ POST /coop/message    │                        │                 │
       │ Authorization:        │                        │                 │
       │   Bearer mcpa_xxx     │                        │                 │
       │──────────────────────>│                        │                 │
       │                       │                        │                 │
       │                       │ 根据 MCP token         │                 │
       │                       │ 找到绑定的 BUC token    │                 │
       │                       │                        │                 │
       │                       │ POST /tools/call       │                 │
       │                       │ Authorization:         │                 │
       │                       │   Bearer buc_yyy       │                 │
       │                       │───────────────────────>│                 │
       │                       │                        │                 │
       │                       │                        │ GET /user_info  │
       │                       │                        │ ?token=buc_yyy  │
       │                       │                        │────────────────>│
       │                       │                        │                 │
       │                       │                        │ BUC User Info   │
       │                       │                        │<────────────────│
       │                       │                        │                 │
       │                       │                        │ 权限验证 &      │
       │                       │                        │ 业务逻辑        │
       │                       │                        │                 │
       │                       │         Response       │                 │
       │                       │<───────────────────────│                 │
       │       Response        │                        │                 │
       │<──────────────────────│                        │                 │

如上图，网关会带上 BUC Token（buc_yyy）调用 Provider 的接口，Provider 需要用该 token 去查询 BUC，获取相应的 BUC 账号信息后进行权限验证并执行业务逻辑。

网关在 BUC 授权下的额外行为

除了上面的标准行为（即网关会带上 BUC Token 调用 Provider 的接口）之外，网关在 Provider 使用 BUC 授权服务器时提供以下额外特性：

  • 网关会去 BUC 系统中换取 token 对应的 BUC 账号信息，并在工具调用上下文中添加工号、域账号等信息，Provider 可以读取这些字段，而不用再次查询 BUC 系统。
    • 如何获取这些信息详见：Java Aone MCP 研发手册 和 Aone FaaS MCP 研发手册
  • 提供基于 BUC 账号的 token 管理能力
    • 已提供，详见 Aone 开放平台 个人页面

语雀 OAuth

使用语雀 OAuth2 进行身份认证，MCP 工具在运行时可获取 语雀 token。用于实现语雀相关的 MCP Server。

其他授权服务器

如果需要使用其他 OAuth 授权服务器，请联系 @史飞超(飞超)。
